# 采购询价跟进助手

把条件问清，把原话留下。

当前阶段：受控实验完成 · 本地原型 · 真实业务待验证

## 项目概览

采购询价跟进助手面向小批量定制采购：把各家分散的单价、税费、打样费、运费、起订量和交期整理成一张能查原话的对比表。先通过模拟供应商的受控实验检查机制，再做出可操作的本地网页。当前交付是“实验引擎＋本地原型”，还不是对外上线的采购产品。

## 用户问题与目标

给文化衫、帆布袋或赠品询价时，便宜的单价可能附带额外费用，不同供应商的条件也不一定能直接比较。需求中途变化，还容易把旧报价当成新报价。

这些是本项目要验证的问题假设，尚未通过真实用户访谈确认。目标是问全条件、保留出处、避免串号，并检验“每家独立跟进”是否值得增加系统复杂度。

## 方案与取舍

询价流程：录入需求 → 为每家建立独立跟进 → 补齐报价条件 → 对比到手总价并查原话 → 需求变更后重新确认 → 记录选择。

实验中，每家跟进员只接收本家对话，协调员只接收结构化字段与出处；使用同一模型的单上下文基线做对照，规则评分，不用模型裁判。冻结虚构数据与评分规则，最后只在留出集评估一次。

网页提供专属报价页、缺项或含糊内容追问、原话侧栏、失效价格与选择记录。网页追问采用规则模拟，收费模型用于独立实验。暂不接淘宝、1688或微信，不代下单，不把本机链接当成公网供应商入口。

## 开发实现流程

1. **把产品问题变成可验收目标**：从PRD拆出字段准确、费用完整、出处可追溯与上下文隔离四个目标；先定义通过门槛，再开发和运行实验。

2. **冻结基准，保留一次真正的考试**：固定生成23家虚构供应商，分为15家开发集与8家留出集。开发集用于检查与提示词选择，留出集只做一组最终评估，不反复挑选成绩。

3. **跑通独立跟进与出处校验**：接通DeepSeek真实调用，分开协调员、跟进员和模拟供应商的输入；报价格子记录消息ID与逐字原话，计算到手总价，保留改价历史。

4. **比较规模、变更和记忆**：在3、8、15家规模下对照独立上下文与单上下文；数量变更后让旧单价失效。记忆实验仅读取本家已观察对话，并固定档案快照以减少重复间污染。

5. **把流程落成可操作的本地原型**：实现需求录入、每家专属报价表单、规则式追问、报价对比、原话侧栏、需求变更和记录选择。用mock测试与浏览器操作验证，明确网页尚未接通真实AI跟进。

6. **审计结果，交付可复查材料**：检查原话后发现拦截误报，保留结果并公开比较限制。整理运行记录、报告、测试与一键启动入口，把机制验证和真实需求验证分开。

## 阶段成果

核心验证：留出集隔离组字段准确率 92.06%（174/189），坑识别率 82.05%（32/39），达到PRD的G2门槛。比例按全部固定重复合并分母计算，不挑最好的一次。

工程交付：完成3、8、15家规模对照、需求变更与记忆实验，共保留 38 次运行，包括修复前失败记录。44 项mock测试通过，覆盖PRD的17类验收；本地网页主流程和干净环境安装已验证。

结论边界：拦截器会把部分列表序号误判为别家金额，改变后续追问，干扰隔离组与基线比较。因此，G2通过不能证明多agent更好或必要。出处逐字存在也不等于语义充分支持，次品条款的严格文本评分受标点影响。当前没有真实用户、节省时间、节省费用或商业转化的证据。

## 下一步

保留本轮冻结结果，先修复拦截误报，再制定新实验计划并使用新的独立留出集验证。随后补上网页真实AI跟进与对外访问所需的权限、部署能力。

产品验证分两步：先访谈采购者，核实实际询价家数、隐藏费用与沟通方式；再在真实采购中观察供应商是否愿意填写报价页。是否继续多agent、是否采用报价页作为主入口，取决于这些新证据。
